# ADR-001: Движок сканера — один общий модуль для сайта, CLI и десктопа

Дата: 2026-11-02. Статус: принято. Источник: spec R01/G01/R04, interfaces.md.

## Контекст

Весь конвейер сканирования жил внутри единственного Next.js-роута (`src/app/api/scan/route.ts`, ~380 строк неэкспортируемых функций). Бриф добавил ещё две поверхности — команду в терминале (G01) и нативное Windows-приложение (R04). Дублировать конвейер трижды или тащить Next внутрь CLI было нельзя.

## Решение

`src/engine/` — модуль без Next-зависимостей: Playwright + axe, security- и native-проверки, скоринг, отчётная модель, словарь советов. Шов наружу: `runScan(options: ScanOptions): Promise<ScanResult>`, `runSecurityAudit(url, init)`, `runNativeAudit(url, mode)` (только CLI/десктоп), реестр `SECURITY_CHECKS`, типы `ScanResult`/`Violation`/`SecurityFinding`/`NativeFinding`, `normalizeUrl`/`assertPublicHttpUrl` (SSRF-фильтр). API-роут — тонкая обёртка без логики сканирования; CLI (`src/cli/bin.mjs`, commander + picocolors, без сборки — type-stripping Node ≥22.6) рендерит терминальный отчёт из той же ScanResult-модели; десктоп зовёт движок как sidecar (см. ADR-003). CLI/десктоп берут глубокие импорты `@/engine/report|scan|advice` — engine/index.ts под них не расширяли.

## Последствия

- Один источник правды для трёх поверхностей: правило, проверка или формат отчёта добавляются один раз и везде появляются одновременно; ноль дублирования форматов.
- Жёсткое правило: внутри engine нет `next/*` — это проверяется самим фактом запуска из CLI.
- Цена: ScanResult — замороженный контракт, новые поля только additive, переименования и смена формы запрещены (R08i); функции localStorage (тарифы, история, аккаунт) в движок не вошли — веб держит их в браузере, десктоп в файле app data, CLI их не имеет вовсе; `src/lib/security.ts` удалён — все импорты переведены на `src/engine/`.
