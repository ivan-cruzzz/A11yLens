# ADR-004: Нативные проверки — только пассивные, с лимитами и режимами интенсивности

Дата: 2026-11-02. Статус: принято. Источник: spec R05–R05.4, R04.2; interfaces.md, контракт «скан чужого сайта».

## Контекст

Браузеру недоступны TLS, TCP-порты, поддомены, CVE библиотек и почтовые записи домена. «Проверка на возможную кибератаку» из брифа на брифинге сузили до «искать слабые места, не ловить атаки». Сканер ходит по чужим сайтам, значит нужен явный этический и юридический предел интенсивности.

## Решение

`runNativeAudit(url, mode)` — только CLI/десктоп: TLS-аудит (срок ≤30 дней warning, истёк/самоподпис high, SAN/имя, TLS 1.0/1.1 high); топ-100 TCP-портов параллельно с таймаутом 1с, весь скан ≤30с; поддомены пассивно (crt.sh + DNS-резолв, без брутфорса); CVE по версиям фронтенд-библиотек со страницы через бесплатный OSV (`api.osv.dev`); SPF/DKIM/DMARC через DNS TXT с кешем на скан (`createTxtCache`); инвентарь технологий (A01). Этика: никаких брутфорсов и нагрузочных проб; режимы `quick|normal|deep` (`NATIVE_MODES`) меняют паузы/таймауты/лимиты, но не набор векторов; ложные срабатывания давятся сверкой тела пробы с сигнатурой (опыт `probeSensitiveFiles` против SPA-фолбэков). Инфраструктура: реестр `NATIVE_CHECKS` (6) — источник checksRun; зависимости инъекцией (`auditTls`/`scanPorts`/`findSubdomains`/`checkLibraryCves`/`auditEmailSecurity`/`detectTechnologies`) — тесты идут по фикстурам и мокам, в сеть не ходят. Внешние сервисы — только бесплатные без ключей (OSV, crt.sh); HIBP исключён (платный ключ); новый внешний сервис = вопрос пользователю.

## Последствия

- Честное покрытие того, чего веб не видит, без правовых рисков; «глубже» = медленнее и больше страниц, а не агрессивнее.
- Цена: пассивность = слепые зоны — экзотические порты вне топ-100 невидимы, активная эксплуатация не проверяется никогда; данные только из публичных источников (crt.sh/OSV могут быть неполными или медленными); потолок «глубины» задан договором с пользователем, технологически «докрутить» его нельзя без пересмотра ADR.
