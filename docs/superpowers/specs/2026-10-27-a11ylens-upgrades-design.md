# A11yLens — доработки: регистрация, подписки, полиш вёрстки

Дата: 2026-10-27
Статус: утверждено в диалоге (пользователь подтвердил дизайн и выбор «демо-регистрация» + «мок-оплата»)

## Цель

Довести A11yLens до целостного демо-продукта: регистрация с выбором аватара,
система подписок с мок-оплатой, и исправление вёрстки отчёта/шапки. Всё в единой
монохромной чёрной стилистике, без БД и внешних платёжных систем — данные в
localStorage, оплата — демо-модалка.

Не входит: реальная аутентификация на сервере, реальные платежи, БД, e-mail.

## Пакет A. Регистрация с выбором лица

### Поведение

- Новый маршрут `/register` (клиентский компонент).
- Любой вход на `/scan` и клики по CTA лендинга («Открыть сканер», «Проверить сайт»)
  проверяют аккаунт. Если аккаунта нет — переход на `/register?next=<исходный путь>`
  (например `/register?next=/scan?url=example.com`). После завершения регистрации —
  редирект на `next` (по умолчанию `/scan`).
- Экран `/register`: одна карточка, два шага.
  - Шаг 1: имя, e-mail, пароль + подтверждение. Клиентская валидация
    (непустые поля, корректный e-mail, пароль ≥ 8 символов). Пароль никуда не
    сохраняется и никуда не отправляется.
  - Шаг 2: выбор лица (переиспользуется `AvatarPicker`/`FaceArt` из
    `components/kokonutui/avatar-picker.tsx`) + поле «Название сайта»
    (предзаполнено хостом из `next`, если он там есть). Кнопка «Создать аккаунт».
- Повторный вход на `/register` при существующем аккаунте — редирект на `/scan`.

### Данные

Новый `lib/account.ts` по образцу `lib/history.ts`, ключ `a11ylens:account:v1`:

```
type Account = {
  displayName: string;   // имя из шага 1
  email: string;
  avatar: { displayName: string; variant: number; face?: FaceArt };
  siteName: string;      // «Название сайта» из шага 2
  createdAt: string;     // ISO 8601
};
```

API: `loadAccount()`, `saveAccount(account)`, `clearAccount()` — все с защитой от
SSR (`typeof window`). Пароль не входит в структуру.

### Шапка

- `ProfileDropdown` вместо захардкоженного «Локальный профиль» получает аккаунт:
  аватар (FaceArt) + имя, e-mail; в меню добавляются «Управление подпиской»
  (переход на `/pricing`) и «Выйти» (`clearAccount()` + редирект на `/`).
- На лендинге в шапке тоже показывается аккаунт (сейчас там только кнопка
  «Открыть сканер»); при отсутствии аккаунта — без профиля, как сейчас.

## Пакет B. Подписки (мок)

### Тарифы

```
type PlanId = "free" | "pro" | "business";
type Plan = {
  id: PlanId;
  name: string;
  priceRub: number;           // 0 / 990 / 2990
  scansPerDay: number | null; // 5 / 100 / null = безлимит
  bulk: boolean;              // массовая проверка
  pdf: boolean;               // экспорт PDF
};
```

### Данные

Новый `lib/subscription.ts`, ключи:
- `a11ylens:plan:v1` — текущий `PlanId` (по умолчанию `free`);
- `a11ylens:usage:v1` — `{ date: "YYYY-MM-DD", count: number }`.

API: `getPlan()`, `setPlan(id)`, `getUsageToday()`, `recordScan()`,
`canScan()` (сравнивает счётчик с лимитом плана, сбрасывает при смене даты),
`PLANS` (константа с тремя тарифами).

### Экран `/pricing`

- Три карточки тарифов в монохромной стилистике. Pro выделен рамкой
  (`border-foreground/40`), не цветом. Кнопки: «Текущий план» (disabled) /
  «Оформить Pro» / «Оформить Business» / «Перейти на Free».
- «Оформить» открывает демо-модалку: маскированный ввод номера карты
  (формат 0000 0000 0000 0000, срок, CVC — только валидация длины), кнопка
  «Оплатить N ₽» с состоянием загрузки ~1.2 с, затем «Подписка оформлена» и
  активация плана (`setPlan`).
- Переключение на Free — сразу, без платёжной формы, с текстом-подтверждением
  о том, что лимиты Free станут активны сразу.

### Гейтинг в UI

- Перед каждым запуском сканирования (одиночного и каждого из массовых) —
  `canScan()`; если лимит исчерпан: модалка «Лимит исчерпан» со счётчиком
  «использовано N из M сегодня» и кнопками «Оформить Pro» и «Попробовать завтра».
  Успешный скан вызывает `recordScan()`.
- Массовая проверка и экспорт PDF при `free` показываются с иконкой замка и
  подписью «Pro»; клик ведёт на `/pricing`. Сами действия не выполняются.
- Бейдж плана — в меню профиля («Тариф: Pro»).

## Пакет C. Вёрстка и полиш

1. **Блок прогресса после сканирования** (`app/scan/page.tsx`):
   сетка `lg:grid-cols-2` с пустой правой колонкой заменяется на одну колонку
   `max-w-md` по центру во время сканирования (CurrencyTransfer + Loader рядом);
   после готовности CurrencyTransfer скрывается — первым экраном идёт бенто-панель.
   Заголовок «Отчёт: …» и `SlideToConfirm` — flex-строка с выравниванием по центру
   вертикали, переносятся на мобильных.
2. **Список нарушений** (контент `SmoothTab`): `space-y-3` →
   `grid gap-3 sm:grid-cols-2` для карточек нарушений; пустое состояние остаётся
   на всю ширину.
3. **Скриншоты** (`LightboxGrid` / обёртка в `scan/page.tsx`): плитки одного
   размера (`aspect-video`, `object-cover`, нейтральный фон-заглушка
   `bg-card`), не больше 12 плиток + плитка «+N ещё», открывающая лайтбокс
   с остальными.
4. **«Сохранить и поделиться»**: сетка остаётся `lg:grid-cols-2`, карточки
   `h-full flex flex-col`, PDF-кнопка внизу второй карточки (`mt-auto`),
   стиль кнопки — нейтральный основной (как остальные CTA).
5. **Профиль в шапке**: обёртке профиля — отступ от верхнего края,
   вертикальное центрирование в h-16; проверяется на обеих страницах.
6. **Общий полиш**: единый ритм секций на `/scan` (`mt-12/16`), одинаковые
   `rounded-2xl border bg-card/50` для карточек, ровные отступы футера.

## Обработка ошибок и краевые случаи

- localStorage недоступен (приватный режим): все lib-функции молча возвращают
  значения по умолчанию, приложение работает без аккаунта.
- `next`-параметр валидируется: только внутренние пути (начинаются с `/`),
  иначе `/scan`.
- Смена дня сбрасывает счётчик проверок; смена плана вниз при исчерпанном
  лимите — блокирует новые сканы до следующего дня (сообщение в модалке).
- Аккаунт удалён при существующей истории — история остаётся, профиль снова
  предлагается при следующем скане.
