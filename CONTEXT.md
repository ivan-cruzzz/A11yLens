# CONTEXT.md — словарь проекта A11yLens

Как здесь называются вещи. Источник истины: `.autopilot/2026-11-02-a11ylens-upgrade--wip/` (spec, manifest, interfaces, notes). Если термин из этого списка — он значит ровно то, что ниже, и не переиспользуется в другом смысле.

- **ScanResult** — единственная модель отчёта скана (`engine/types`): url, скоры, violations, security, pages. Веб-отчёт, CLI-рендер и десктоп читают один тип; изменения только additive, переименовывать поля запрещено (R08i).
- **SecurityFinding** — находка security-проверки: `{id, title, severity, detail, evidence?, why?, recommendation}`. Без заполненного evidence проверка не считается сработавшей.
- **Нативные проверки (NativeReport)** — проверки, недоступные браузеру: TLS, топ-100 портов, поддомены, CVE библиотек, SPF/DKIM/DMARC, инвентарь технологий. Выполняет `runNativeAudit(url, mode)`, доступно только CLI и десктопу; отчёт — `NativeReport{score, findings, checksRun, technologies, subdomains, openPorts, degradations}`.
- **evidence (доказательство)** — строка с конкретным фактом находки: точный заголовок, имя куки или фрагмент тела ответа. Правило контракта: нет evidence — нет находки; поэтому SPA-фолбэк, отдающий 200 на любой путь, не даёт ложных срабатываний.
- **План исправления** — раздел отчёта: топ-действия по убыванию эффекта на скор, каждое с оценкой усилия (минуты/часы/дни, `EFFORT_LABELS`). Строит `buildRemediationPlan` из словарей, без ИИ.
- **Симуляция «если исправите»** — `simulateScores(result, fixedIds)`: пересчёт обоих скоров (a11y + security) при отметке находок исправленными, без повторного сканирования; в UI — чекбокс у находки.
- **Режимы quick / normal / deep** — единый конфиг интенсивности (`NATIVE_MODES`, в десктопе `MODES`): меняют паузы, таймауты и лимиты (`--mode`, `--max-pages 2|4|8`, `--timeout 45|90|180с`), но никогда — набор проверок. Этика сканирования одинакова во всех поверхностях.
- **SECURITY_CHECKS-реестр** — массив `{id, area, title}` всех security-проверок в engine (20 штук). Единственный источник для checksRun и списка проверок в UI; захардкоженное число проверок — ошибка. Аналог для нативных проверок — `NATIVE_CHECKS` (6).
- **checksRun** — сколько проверок реально выполнялось в аудите; считается как длина соответствующего реестра, никогда не пишется числом руками (исторический баг «19 при 20» закрыт именно этим).
- **Sidecar** — CLI-движок, собранный в отдельный бинарник `a11ylens-engine.exe` и лежащий рядом с Tauri-приложением. Общение: Tauri вызывает `run_engine(args)`, читает stdout команды `--json` — `{scan: ScanResult, native: NativeReport|null}`.
- **SEA** — Node Single Executable Application: сборка движка в самостоятельный exe без установленного Node на машине пользователя; собирает `scripts/build-sidecar.mjs`.
- **Бенто-панель** — сетка виджетов отчёта на `/scan` (компоненты `WidgetGrid`/`WidgetGridItem` из kokonutui bento-grid): карточки скоров, счётчиков и сводок в стиле bento. Термин из UI-библиотеки проекта, не из DOM.
- **Темы / акцент** — `data-theme` (`light|dark|system`) на `<html>` + CSS-токен `--accent` поверх монохромной палитры; выбор хранится в `a11ylens:theme:v1`; тест контраста обеих тем (`tests/ui/theme-contrast.test.ts`) обязателен — свой сканер не должен находить контраст-нарушения на своих экранах.
- **redactBody** — PII-маскирование снятых тел ответов в `engine/scan.ts`: секреты и персональные данные вычищаются до того, как фрагмент попадёт в отчёт, evidence или localStorage. Всё, что кладётся в отчёт, проходит через него.
