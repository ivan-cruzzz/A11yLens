# A11yLens Desktop

Нативное Windows-приложение (Tauri 2): ввод URL → прогресс по этапам → полный
отчёт (доступность + браузерный security + нативные проверки: TLS, порты,
поддомены, CVE, SPF/DKIM/DMARC) с локальной историей сканов.

Движок сканирования — **общий с CLI**: sidecar-бинарник `a11ylens-engine.exe`
(Node SEA поверх `src/cli`), окно не запускает собственный сканер и не считает
скоры — все они приходят в отчёте от движка.

## Архитектура

```
desktop/
├── src/                 # React-окно (свои компоненты, визуальный язык веба:
│   ├── App.tsx          #   монохром zinc, бенто-панель, скоры, находки)
│   ├── lib/             # чистые модули: конфиг режимов, сборка аргументов
│   │                    # sidecar, разбор JSON-отчёта, полнота, история
│   └── ui/              # FirstRun (этика+Chromium), форма, прогресс, отчёт
├── src-tauri/           # Rust-бэкенд: state/history в app data, запуск sidecar,
│   ├── tauri.conf.json  # только Windows: NSIS + MSI, ярлык, sidecar externalBin
│   └── binaries/        # a11ylens-engine-<triple>.exe (артефакт SEA-сборки)
├── sidecar/             # вход SEA-бинарника + sea-config.json
└── scripts/             # gen-icons.mjs, build-sidecar.mjs
```

Данные живут в `%APPDATA%\ru.a11ylens.desktop\`: `state.json` (согласия первого
запуска, тема) и `history.json` (история сканов, до 50 записей, без тяжёлых
скриншотов). Это файлы app data — не localStorage и не localStorage-ключи веба.

## Поведение, зафиксированное в коде

- **Первый запуск** — экран этики «только свои сайты или с разрешения» и
  согласие на докачку Playwright-Chromium. Без обоих согласий кнопка «Принимаю»
  неактивна: скан не запускается (R04.1/R04.2).
- **Режимы быстро/обычно/глубоко** — один конфиг `desktop/src/lib/modes.ts`
  переводит выбор в флаги CLI: `--mode quick|normal|deep`, `--max-pages`
  (2/4/8), `--timeout` (45/90/180 с). Режимы меняют таймауты/лимиты, не набор
  векторов (R04.2).
- **Обрыв сети** (R04.3): если sidecar упал без JSON или отчёт пришёл не по
  всем запланированным страницам (а также при `security.error` /
  `native.error`), попытка сохраняется в историю с пометкой «неполный».
  Кнопка «Продолжить» перезапускает sidecar с `--max-pages` = остаток плана
  (просканированные страницы заново не открываются), а не с нуля. Деградации
  внешних сервисов (crt.sh/OSV недоступны) — заметки, отчёт считается полным.
  Движок не имеет флага «продолжить с N-й страницы», поэтому «продолжение» —
  это новый прогон остатка лимита страниц; механика выбрана из-за фиксированного
  контракта CLI и описана здесь сознательно.
- **Прогресс** — этапы тикают по таймеру режима (движок печатает отчёт одним
  JSON в конце; событийного прогресса у CLI нет), реальный сигнал — завершение
  процесса. Окно при этом не блокируется: sidecar в отдельном процессе
  (`CREATE_NO_WINDOW`).

## Сборка из исходников (Windows 10+)

Требования: Node ≥ 22.6, Rust (cargo), WebView2 Runtime (есть на актуальной
Windows 10/11; на «чистой» системе установщик сам докачает bootstrapper'ом).

```bat
cd desktop
npm install                 :: фронт-тулзы (vite, react, typescript, tauri-cli, esbuild, postject)
npm run gen:icons           :: иконки в src-tauri/icons (делается один раз)
npm run build:sidecar       :: SEA-бинарник src-tauri\binaries\a11ylens-engine-<triple>.exe
npm run tauri build         :: установщики: src-tauri\target\release\bundle\{nsis,msi}
```

После сборки установщик (`*-setup.exe`, NSIS, установка «только для меня»,
ярлык в меню «Пуск») ставит на чистую Windows: окно, sidecar-движок и
`pw/browsers.json` рядом с ним. Node и глобальные браузеры на машине
пользователя не нужны: Playwright-Chromium докачивается при первом скане по
согласию пользователя (с официального CDN Playwright; без него скан не
стартует, приложение честно повторяет запрос).

Dev-режим без SEA: `npm run tauri dev` из `desktop/` — окно запускает движок
через `node src/cli/bin.mjs` репозитория (фолбэк в `resolve_engine`,
`desktop/src-tauri/src/lib.rs`). Переопределить путь к движку можно переменной
`A11YLENS_ENGINE` (полный путь к exe или JS-ланцеру).

## Проверки

```bat
npm test                              :: из корня репозитория — 224 теста движка/CLI (не трогаем)
npx vitest run --config desktop/vitest.config.mts   :: 34 теста швов десктопа
npx tsc -p desktop\tsconfig.json      :: типы окна (strict)
node scripts\build-sidecar.mjs        :: включает дымовой прогон бандла до вшивания
```

Тесты десктопа покрывают чистые швы UI-слоя: конфиг режимов и сборку аргументов
sidecar (один конфиг с CLI `--mode`), разбор stdout движка (мусор/обрыв → null),
оценку полноты отчёта и остаток страниц, slim-срез для истории, лимит истории.

## Границы

- Только Windows (решение пользователя: «без линукса»).
- Стандарт/устройство фиксированы (WCAG AA, desktop) — у CLI `scan` нет таких
  флагов; когда появятся в `src/cli`, добавить в `modes.ts` — одно место.
- Скриншоты в отчёте окна не показываются и в историю не пишутся (размер);
  полные отчёты со скриншотами — веб-версия.
