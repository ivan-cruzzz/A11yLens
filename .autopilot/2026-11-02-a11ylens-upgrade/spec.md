# Спецификация: A11yLens — качество, нативные проверки, ПК-софт и CLI

## Задача

Владелец или разработчик сайта хочет знать, что на сайте сломано и уязвимо, **до** того, как об этом узнают посетители с ограниченными возможностями или атакующие. Сейчас сканер находит проблемы, но исследование поверхностное (одна страница, находки без доказательств), разбор советов — rule-based демо-уровня, глубокие проверки (TLS, порты, поддомены, CVE) в браузере невозможны, а пользоваться можно только через веб. Пользователь сказал: «улучши качество скриптов и исследований ошибок сайта, сделай более качественный разбор проблем сайта, сделай софт на пк для более качественной проверки на возможную кибератаку и тд, сделай более приятный интерфейс и дай новые идеи для сайта» — и добавил на брифинге: проверка сайта через терминал, без Linux-сборок, реальный ИИ не подключаем.

## Решение

Сканер становится глубже и честнее: находит больше (несколько страниц, доказательства к каждой находке), объясняет понятнее (план исправления по приоритету с оценкой усилия и эффектом на скор, без внешнего ИИ), проверяет то, что браузеру недоступно (TLS, порты, поддомены, CVE библиотек, почтовые записи) — и доступен тремя способами: сайт, нативное Windows-приложение и команда в терминале. Интерфейс — с акцентным цветом, тёмной и светлой темами, легче и просторнее. Отдельным документом — приоритизированные идеи развития сайта.

## Решения по реализации

- **`src/engine/` — общий движок** без Next-зависимостей (Playwright, axe, security/native-проверки, скоринг, отчётная модель, советы). Его импортируют API-роут, CLI и сборка для десктопа — один источник правды для трёх поверхностей.
- **CLI на commander + picocolors**, вход `src/cli/`, bin `a11ylens`; отчёт в терминале рендерится из той же ScanResult-модели — почему: ноль дублирования форматов.
- **Tauri 2, только Windows**: UI переиспользует React-компоненты веба; сканирование — через CLI-движок как sidecar (Node SEA-бинарник) — почему: не тащим Electron, движок один.
- **Vitest** для юнит-тестов — TS из коробки, без жасмина; фикстуры — снятые HTML/заголовки в `tests/fixtures/`, self-scan страница для smoke.
- **Внешние бесплатные API без ключей**: OSV (`api.osv.dev`) для CVE, crt.sh для поддоменов; всё остальное локально (Node `tls`/`dns`/`net`). HIBP не берём — платный ключ.
- **Темы через CSS custom properties** `data-theme` на `<html>` + акцентный токен `--accent`; сохранение выбора в localStorage рядом с прочими ключами.
- **Скоринг в одном модуле** (`engine/scoring.ts`): веса критичности и severity — единственный источник; веб, CLI и десктоп считают одинаково.
- **Режимы интенсивности** (быстро/обычно/глубоко) — единый конфиг пауз/таймаутов/лимитов для CLI и десктопа — почему: этика сканирования чужих сайтов одинакова везде.
