## Что должно заработать

Сканер живёт в `src/engine/` без Next-зависимостей и вызывается тонким API-роутом. Все константы скоринга и словари критичности — в одном месте. `npm test` (vitest) гоняет юнит-тесты ядра на фикстурах, `npm run scan:self` — smoke по локальной странице с подложенными нарушениями. Сбой аудита безопасности виден в отчёте, пробы идут параллельно, analyze() с таймаутом, SSRF-фильтр закрывает link-local и десятичные IP.

## Критерии приёмки

- [ ] `src/app/api/scan/route.ts` не содержит логики сканирования — только валидация входа и вызов `runScan()` из `src/engine/`
- [ ] `npm test` зелёный: security-проверки на позитивных и негативных фикстурах, скоринг, scan-diff, advice, normalizeUrl/SSRF-фильтр
- [ ] каждая security-проверка из реестра имеет хотя бы один тест; `checksRun` вычисляется из реестра, а не захардкожен
- [ ] runScan/scanBulk и IMPACT-словари не дублируются (grep по именам констант находит один источник)
- [ ] сбойный securityAudit отражается в отчёте строкой ошибки, а не `undefined`; analyze() завершается по таймауту
- [ ] SSRF-фильтр отклоняет `169.254.x.x`, `0.0.0.0`, десятичные/восьмеричные IP-формы и прочие обходы (тестами)
- [ ] `npm run scan:self` поднимает локальную фикстурную страницу, сканирует её и находит подложенные нарушения; `npm run build` проходит
