## Что должно заработать

Пробы чувствительных файлов не следуют редиректам (3xx = проба не удалась) — редирект на внутренний адрес не уводит evidence. Fetch-recorder не подменяет глобальный fetch безусловно — параллельные сканы не убивают запись друг друга. Все словари порядка (impact, severity) живут в одном источнике `engine/scoring.ts`; локальные дубли удалены.

## Критерии приёмки (находки ревью ветки, дословно)

- [ ] «probeSensitiveFiles делает fetch без redirect: "manual" — сканируемый сайт может 302-редиректом пробы увести на http://169.254.169.254/…: SSRF-фильтр проверяет только исходный хост» → добавить `redirect: "manual"` (как в auditHttpsRedirect, security.ts:277) и трактовать 3xx как «проба не удалась»; тест: фикстура с редиректом не даёт находку
- [ ] «withFetchRecorder подменяет и восстанавливает globalThis.fetch безусловно — при двух параллельных сканах первый завершившийся возвращает нативный fetch, убивая запись второго» → recorder-fetch через зависимости (параметры уже есть) либо условное восстановление `if (globalThis.fetch === recorded)`; тест на два параллельных рекордера
- [ ] «локальный impactRank ({critical:0…minor:3}) в ai-chat.tsx дублирует IMPACT_ORDER из engine/scoring.ts» → удалить, импортировать IMPACT_ORDER, сортировать им
- [ ] «словарь порядка severity {high:0, medium:1, low:2, info:3} определён в трёх местах (report.ts:317, security.ts:463, native/index.ts:93)» → экспортировать SEVERITY_ORDER из engine/scoring.ts рядом с SEVERITY_WEIGHTS и использовать во всех трёх
- [ ] `npm test` зелёный (все прежние + новые тесты на редирект-фикстуру и параллельные рекордеры), `npm run build` зелёный
